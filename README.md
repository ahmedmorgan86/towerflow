# TowerFlow · AD

منصة إدارة عقارات أولية قابلة للتشغيل، عربية RTL وإنجليزية، بواجهة كحلي وتركواز ووضع داكن. لا تعتمد على أي خدمة أو مفتاح ذكاء اصطناعي.

## التشغيل

يتطلب Node.js 24. ثبّت الاعتماديات عبر `npm ci`، ثم شغّل `npm run local` لنسخة PostgreSQL محلية مستديمة على `http://localhost:3000`. أنشئ حسابك من الواجهة؛ لا توجد كلمات مرور افتراضية. هذه النسخة تستخدم PGlite للاختبار والتطوير فقط، وليست قاعدة إنتاج مشتركة.

للإنتاج استخدم PostgreSQL على Neon. ضع `DATABASE_URL` في `.env.local` محليًا أو كـSecret في Vercel، و`APP_ORIGIN` يساوي أصل الموقع HTTPS بالضبط. نفّذ `npm run db:setup` مرة؛ يتعرف على التهيئة السابقة. شغّل `npm run dev` للاتصال بالقاعدة الخارجية. لا تكشف رابط القاعدة للمتصفح.

## ما نُفذ

- مؤسسات متعددة، ستة أدوار، عزل صفوف RLS، ومفاتيح خارجية مركبة تمنع الربط بين المؤسسات.
- عقارات وأبراج ووحدات وملاك ومستأجرون وعقود وملكيات؛ إشغال الوحدة يتبع حالة العقد.
- فواتير مسودة ثم إصدار وترحيل محاسبي، تحصيل جزئي ونهائي، منع التحصيل الزائد وتكرار المرجع.
- محاسبة مزدوجة، دليل حسابات، قيود متوازنة غير قابلة للتعديل بعد الترحيل، ميزان مراجعة وتصدير CSV.
- طلبات مصروفات مع اعتماد مدير آخر؛ الاعتماد يرحّل قيد الصرف تلقائيًا. النموذج الحالي يفترض الصرف النقدي عند الاعتماد.
- صيانة وأصول وفنيون، إعلانات، إشعارات داخل التطبيق، وتدقيق تلقائي دون تخزين كلمات المرور أو محتوياتها في السجل.
- بوابة سكان للقراءة وطلبات الصيانة وفق العقد وسجل المستأجر المرتبط بالمستخدم.
- تطبيق Android أصلي Kotlin/Android Views، يسجل الدخول ويعرض القوائم ويضيف العقارات والوحدات والأطراف والعقود والأصول والفنيين وطلبات الصيانة ويصدر ويحصّل الفواتير. بقية إجراءات التحرير متاحة حاليًا في الويب.

## التسلسل المقترح للاستخدام

1. أنشئ الحساب والمؤسسة، ثم العقار والوحدات.
2. أضف الملاك والمستأجرين والملكيات والعقود.
3. أنشئ الفاتورة ثم أصدرها، وسجّل التحصيل بمرجع فريد.
4. أضف مستخدمًا آخر بعد تسجيله، من شاشة الصلاحيات. اربط الساكن بسجل المستأجر، وأضف مديرًا آخر للموافقات.
5. أضف الأصول والفنيين، ثم طلبات الصيانة.
6. راجع ميزان المراجعة والتدقيق.

## الاختبارات

`npm test` ينفذ اختبارات PostgreSQL/RLS والمحاسبة واختبارات HTTP ضد API حقيقي بقاعدة PostgreSQL مدمجة معزولة. `npm run build` يبني ملفات الويب. مسار GitHub Actions يشغّل الاختبارات ويبني Android Debug وAndroid Lint. نجاح اختبارات PostgreSQL المحلية لا يغني عن تحقق البيئة المنشورة.

## Android

افتح مجلد `android/` في Android Studio، باستخدام JDK 21 وGradle 8.13 وAndroid SDK 35. أو نفّذ `gradle -p android assembleDebug lint`. البناء الآلي ينتج APK للاختبار في GitHub Actions. أدخل عنوان موقع TowerFlow الكامل HTTPS داخل التطبيق. الجلسة في الذاكرة فقط؛ إغلاق العملية يتطلب تسجيل الدخول مجددًا.

Vercel ينشر الويب والخدمة فقط. Android يحتاج بناء APK/AAB وتوقيع إصدار ونشر Google Play منفصلًا. ملفات التوقيع غير مدرجة. النسخة الحالية لا تدّعي اكتمال جميع وظائف Android أو اختبارها على أجهزة حقيقية.

## حدود الإصدار والعمل التالي

الإصدار 0.4 يضيف بروفايل وصورة وكاميرا، دخول جوجل مع ربط آمن للحساب، صلاحيات إضافية للأعضاء، بنود وضرائب الفواتير، الاستحقاقات الدورية، الصيانة الوقائية، إغلاق الفترات وعكس القيود، تقارير تفصيلية مع CSV وطباعة الصفحة الحالية إلى PDF، ورسائل لكل سكان البرج أو وحدات محددة. Android يتضمن تسجيل جهاز FCM وإشعارات الخلفية؛ وصول الإشعار على جهاز حقيقي لم يُختبر بعد. تفعيل الإرسال يتطلب سر حساب خدمة FCM في Vercel.

ما زال يلزم: استعادة كلمة المرور وMFA والتحقق من بريد تسجيل كلمة المرور، دعوات بريدية، فصل اعتماد المصروف عن دفعه، عملات متعددة وتسويات بنكية، مرفقات وSLA، البريد وSMS والدفع الإلكتروني، تمرين استرجاع النسخ الاحتياطية ومراجعة أمن مستقلة، وإكمال تكافؤ وظائف Android واختباره على أجهزة فعلية. نجاح الاختبارات لا يعني اكتمال ERP أو اعتمادًا محاسبيًا مستقلًا.

لا توجد بيانات تجريبية في الإنتاج. ملفات الأسرار و`node_modules` و`.vercel` وبيانات التشغيل المحلية مستبعدة من Git.
